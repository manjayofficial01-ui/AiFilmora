# F5: AI video tech trends + Windows NLE architecture patterns

## Findings

### [1] OpenAI shipped Sora 2 on Sept 30, 2025 as a video-audio generation model with synchronized dialogue, sound effects, multi-shot world-state persistence, and a "characters" likeness-injection feature, then discontinued the consumer Sora web/app product on April 26, 2026 with the API scheduled to shut down Sept 24, 2026.
- quote: "Today we're releasing Sora 2, our flagship video and audio generation model. ... As of April 26, 2026, the Sora product is no longer available."
- url: https://openai.com/index/sora-2/
- source_type: primary
- published: 2025-09-30 (discontinuation notice updated 2026)
- confidence: high

### [2] OpenAI's official discontinuation guidance confirms Sora web/app were killed on April 26, 2026 and the Sora API will be discontinued on September 24, 2026, with permanent deletion of user data after an export window.
- quote: "The Sora web and app experiences were discontinued on April 26, 2026. The Sora API will be discontinued on September 24, 2026."
- url: https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation
- source_type: primary

### [3] Google DeepMind's current flagship video model is Veo 3.1, which generates natively synchronized audio (dialogue, SFX, ambient), supports "ingredients" reference images for scene/character/object consistency, style reference images, multi-shot scene extension from the last second of a prior clip, and explicit camera controls.
- quote: "Veo 3 lets you add sound effects, ambient noise, and even dialogue to your creations – generating all audio natively. ... Extend clips into longer, more dynamic videos. Use the last second of your first shot to continue the story – while maintaining visual and audio consistency."
- url: https://deepmind.google/models/veo/
- source_type: primary
- published: unknown (Veo 3.1 current as of 2026-09)
- confidence: high

### [4] Runway Gen-4.5 launched Dec 1, 2025 and was ranked #1 on the Artificial Analysis Text-to-Video benchmark with 1,247 Elo, ahead of Google Veo 3 (1,226), Kling 2.5 (1,225), and OpenAI Sora 2 Pro (1,206); it runs inference on NVIDIA Hopper and Blackwell GPUs.
- quote: "With 1,247 Elo points, Gen-4.5 currently holds the top position in the Artificial Analysis Text to Video benchmark ... Inference runs on NVIDIA Hopper and Blackwell series GPUs."
- url: https://runwayml.com/research/introducing-runway-gen-4.5
- source_type: primary
- published: 2025-12-01
- confidence: high

### [5] Runway itself documents residual failure modes of frontier video models that matter for NLE integration: causal-reasoning inversions, object-permanence breaks across frames, and success bias (actions disproportionately succeed).
- quote: "Causal reasoning: effects sometimes precede causes ... Object permanence: objects may disappear or appear unexpectedly across frames ... Success bias: actions disproportionately succeed."
- url: https://runwayml.com/research/introducing-runway-gen-4.5
- source_type: primary
- published: 2025-12-01
- confidence: high

### [6] Runway's research roadmap has shifted from pure clip generation toward real-time interactive "General World Models": GWM Worlds 2 (Sept 3, 2026) generates continuous 720p video at 24 fps and 48 kHz audio in response to free-form text actions and camera motion, and Runway Characters (July 2026) produces real-time audio-synced facial animation from a single image with ~37 ms model time per frame and 1.75 s server turnaround.
- quote: "GWM Worlds 2 turns high-fidelity video and audio generation into real-time interactive simulation. ... generating continuous 720p video at 24 fps and audio at 48,000 Hz ... Runway Characters ... at 24fps in HD resolution ... effective 37 milliseconds of model time per frame."
- url: https://runwayml.com/research
- source_type: primary
- published: 2026-09-03 (GWM Worlds 2); 2026-07-19 (Characters)
- confidence: high

### [7] OpenAI Whisper remains the de-facto open transcript backbone for text-based editing: six model sizes from tiny (39M params, ~1 GB VRAM) through large (1550M, ~10 GB) plus turbo (809M, ~6 GB, ~8x large speed); trained on 680,000 hours of multilingual multitask supervision and MIT-licensed.
- quote: "When scaled to 680,000 hours of multilingual and multitask supervision, the resulting models generalize well ... turbo | 809 M | ~6 GB | ~8x"
- url: https://github.com/openai/whisper
- source_type: primary
- published: 2022-12-06 (paper); repo current 2026
- confidence: high

### [8] SYSTRAN faster-whisper (CTranslate2 reimplementation) is the practical local-GPU transcript engine for desktop NLEs: up to 4x faster than openai/whisper at equal accuracy; on an RTX 3070 Ti 8GB, large-v2 with batch_size=8 does 13 minutes of audio in 17s (fp16) or 16s (int8) using 4.5–6.1 GB VRAM, and supports word-level timestamps plus Silero VAD filtering — critical building blocks for transcript-driven editing.
- quote: "This implementation is up to 4 times faster than openai/whisper for the same accuracy while using less memory. ... faster-whisper (batch_size=8) | fp16 | 5 | 17s | 6090MB ... GPU Benchmarks are Executed with CUDA 12.4 on a NVIDIA RTX 3070 Ti 8GB."
- url: https://github.com/SYSTRAN/faster-whisper
- source_type: primary
- published: unknown (repo current 2026; benchmarks reference v1.1.0)
- confidence: high

### [9] Adobe Premiere Pro has productized text-based editing as a first-class NLE feature set: transcribe source/sequence audio, edit the transcript to cut video, auto-detect and delete pauses, edit speaker names, remove all instances of a speaker, multichannel support, and "Paper Edit" sequence creation from a transcript document.
- quote: "Edit video using Text-Based editing | Overview of Text-Based editing ... Transcribe video ... Edit transcripts using Text-Based Editing | Detect and delete pauses in transcripts ... Create a sequence with Paper Edit"
- url: https://helpx.adobe.com/premiere-pro/using/text-based-editing.html
- source_type: primary
- published: unknown (current Premiere desktop docs 2026)
- confidence: high

### [10] Adobe Premiere's proxy workflow is a complete ingest pipeline: create proxies at import, attach/detach proxies to full-resolution media, reconnect full-res to proxies, export proxies, create/edit/relink offline clips — the standard dual-media pattern any Windows AI NLE must implement for responsive GPU playback.
- quote: "Ingest proxy workflow | Ingest and Proxy workflow | Configure ingest settings | Create proxies | Attach proxies to full-resolution media | Reconnect full-resolution media to proxies | Detach proxies | Export proxies | Create offline clips"
- url: https://helpx.adobe.com/premiere-pro/using/proxy-workflow.html
- source_type: primary
- published: unknown (current Premiere desktop docs 2026)
- confidence: high

### [11] Electron's multi-process architecture for desktop apps is main (Node.js, window lifecycle, native APIs) + one renderer per BrowserWindow (Chromium, web-standard UI) + preload (contextBridge-exposed privileged APIs) + UtilityProcess for CPU-intensive or crash-prone work that must not block the UI thread — the canonical pattern for hybrid media editors.
- quote: "Each Electron app has a single main process ... Each Electron app spawns a separate renderer process for each open BrowserWindow ... The utility process can be used to host for example: untrusted services, CPU intensive tasks or crash prone components."
- url: https://www.electronjs.org/docs/latest/tutorial/process-model
- source_type: primary
- published: unknown (docs current 2026; Electron v44.3.0 examples)
- confidence: high

### [12] Electron official performance guidance for media-heavy apps: never block the main process/UI thread with long-running ops; use worker threads or UtilityProcess for CPU-bound work; avoid sync IPC and sync fs/child_process; defer expensive module loads; bundle code — directly applicable to AI inference and proxy decode jobs in a Windows NLE shell.
- quote: "Under no circumstances should you block this process and the UI thread with long-running operations. ... For long running CPU-heavy tasks, make use of worker threads, consider moving them to the BrowserWindow, or (as a last resort) spawn a dedicated process."
- url: https://www.electronjs.org/docs/latest/tutorial/performance
- source_type: primary
- published: unknown (docs current 2026)
- confidence: high

### [13] Tauri v2 is the lighter Electron alternative for Windows hybrid editors: Rust backend + system webview (no bundled Chromium), minimal apps under 600KB, any HTML/JS/CSS frontend, JS↔Rust `invoke` bindings, and a documented sidecar pattern to ship external binaries (e.g. Node.js or Python ML workers) without requiring a system runtime.
- quote: "Tauri is a framework for building tiny, fast binaries ... a minimal Tauri app can be less than 600KB in size. ... Package a Node.js application to a self contained binary to be used as a sidecar in a Tauri application without requiring the end user to have a Node.js installation."
- url: https://v2.tauri.app/start/ and https://v2.tauri.app/learn/sidecar-nodejs/
- source_type: primary
- published: 2026-07-22 (What is Tauri); 2026-09-03 (sidecar guide)
- confidence: high

### [14] Microsoft DirectML is in "sustained engineering" — supported but no longer receiving new features — with new Windows ONNX Runtime development moved to Windows ML, which dynamically selects the best execution provider (CPU/CUDA/TensorRT/DirectML) per hardware; DirectML itself remains a vendor-agnostic DirectX 12 ML API usable via ONNX Runtime for local NLE AI features on any DX12 GPU.
- quote: "DirectML is in sustained engineering. DirectML continues to be supported, but new feature development has moved to Windows ML for Windows-based ONNX Runtime deployments. Windows ML provides the same ONNX Runtime APIs while dynamically selecting the best execution provider based on your hardware."
- url: https://learn.microsoft.com/en-us/windows/ai/directml/dml
- source_type: primary
- published: 2025-02-10 (ms.date); updated 2026-01-09
- confidence: high

### [15] Premiere Pro's 2026 desktop IA already bundles generative AI as timeline-native features — Generative Extend (frame insertion), Generative Media Tool (text/image-to-video into the project), and Generate Music (beta) — plus an "AI Models preferences" panel, establishing the expected product surface for AI-native Windows editors.
- quote: "Edit with Generative AI | Generative Extend overview | Add frames using Generative Extend | Generative Media Tool overview | Generate media with the Generative Media Tool | Generate Music (beta) overview | AI Models preferences"
- url: https://helpx.adobe.com/premiere-pro/using/proxy-workflow.html (Premiere help TOC, Edit with Generative AI + Preferences)
- source_type: primary
- published: unknown (current Premiere desktop docs 2026)
- confidence: medium
